# 미궁 GUI 고도화 설계

## 목표

`/maze` 하위 명령의 기존 호환성을 유지하면서 플레이어와 운영자가 대부분의 미궁 기능을 인벤토리 GUI에서 수행할 수 있게 한다. GUI는 54칸 상태형 대시보드를 중심으로 구성하고, 남색·보라·금빛의 `심야의 미궁` 스타일을 적용한다.

## 범위

### 플레이어 기능

- 현재 파티와 미궁 진행 상태를 한눈에 확인한다.
- 파티 생성, 온라인 플레이어 초대, 받은 초대 수락·거절, 파티원 추방, 파티 탈퇴·해산을 GUI에서 처리한다.
- 세이브 슬롯별 방 번호, 파티 인원, 저장 시각, 만료 시각을 표시한다.
- 빈 슬롯에서 새 미궁을 시작하고, 기존 슬롯을 재개·덮어쓰기·삭제한다.
- 현재 방의 힌트를 요청·승인·거절·열람한다.
- 1~4인 파티별 순위표를 조회한다.
- GUI에서 정답 입력 모드를 시작한 뒤 채팅 한 줄로 정답을 제출한다. `취소` 입력 또는 제한 시간 만료 시 입력 모드를 종료한다.
- 입장 대기를 취소하거나 진행 중 미궁을 저장 후 퇴장한다.

### 운영자 기능

- `mcpuzzle.admin` 권한이 있는 사용자에게만 관리자 허브를 노출한다.
- 리로드, 생성 월드 검증, 제작 완드 지급, 현재 선택 영역 확인을 GUI에서 실행한다.
- 온라인 플레이어를 선택해 해당 플레이어의 세이브를 열람하고, 슬롯 삭제와 허용된 소유권 이전을 수행한다.
- 서버 콘솔과 자동화 호환을 위해 기존 관리자 명령은 유지한다.

### 제외 범위

- `/maze` 명령 자체와 기존 하위 명령 제거
- 외부 GUI 프레임워크 도입
- 미궁 생성 알고리즘, 맵 데이터, 세이브 데이터베이스 스키마 변경
- 웹 관리자 패널 또는 채팅 외의 자유 텍스트 입력 UI

## 화면 구조

### 메인 대시보드

54칸 인벤토리를 사용한다. 중앙 상태 카드에는 파티 역할, 인원, 미궁 상태, 현재 방, 사용 슬롯을 표시한다. 주변에는 파티, 세이브, 힌트, 순위표, 주요 진행 동작, 받은 초대, 도움말, 관리자 허브를 배치한다.

버튼은 사용자 상태에 맞춰 달라진다. 파티가 없으면 `파티 만들기`, 파티가 있으면 `파티 관리`, 활성 미궁이 있으면 `정답 입력`과 `미궁 나가기`, 대기 중이면 `대기 취소`를 우선 노출한다. 사용할 수 없는 기능은 회색 아이콘과 구체적인 사유를 표시한다.

### 파티와 초대

파티 화면은 파티장, 파티원, 대기 중인 초대를 플레이어 머리 아이콘으로 표시한다. 파티장은 온라인 플레이어 목록에서 초대할 수 있고 파티원을 선택해 추방 확인 화면을 연다. 일반 파티원은 탈퇴 확인 화면을 사용한다. 파티가 없는 플레이어는 파티 생성과 받은 초대 목록을 볼 수 있다.

### 세이브

세이브 화면은 비동기로 목록을 읽는 동안 로딩 상태를 표시한다. 결과가 도착하면 각 슬롯을 빈 슬롯 또는 저장된 슬롯으로 갱신한다. 저장된 슬롯은 현재 방, 원래 명단, 저장·만료 시각을 lore에 표시한다. 좌클릭은 재개, 우클릭은 새로 시작, Shift+클릭은 삭제이며 덮어쓰기와 삭제는 별도 확인 화면을 거친다.

### 힌트와 순위표

힌트 화면은 활성 미궁이 없을 때 비활성 사유를 표시한다. 활성 미궁에서는 세 단계 힌트, 다음 힌트 요청, 파티장 승인·거절을 제공한다. 순위표는 1~4인 탭을 제공하고 로딩 후 상위 10개 기록을 플레이 시간, 실패 수, 힌트 사용량과 함께 표시한다.

### 관리자 허브

관리자 화면은 권한을 다시 확인한 뒤에만 동작한다. 서버 상태를 바꾸는 리로드, 삭제, 소유권 이전은 확인 화면을 거친다. 월드 검증, 완드 지급, 선택 영역 출력은 즉시 실행하되 결과 메시지를 그대로 사용자에게 전달한다.

## 시각 디자인

- 배경 테두리는 짙은 남색 유리판, 섹션 강조는 보라색, 주요 실행은 금빛·초록색, 위험 동작은 붉은색으로 구분한다.
- 현재 리소스팩의 `PuzzleItemModel` 아이콘을 우선 재사용하고, 추가 기능에는 플레이어 머리와 의미가 명확한 바닐라 아이템을 사용한다.
- 모든 버튼 lore는 `현재 상태 → 동작 설명 → 조작법` 순서로 작성한다.
- 빈 공간도 장식 아이템으로 채워 클릭 가능한 영역과 장식 영역을 명확히 구분한다.
- 위험 동작 확인 화면은 초록 확인과 빨강 취소를 좌우 대칭으로 배치한다.

## 구조

- `MazeMenu`는 Bukkit 이벤트 수신, 화면 전환, 사용자별 임시 입력 상태를 담당한다.
- 화면 렌더링과 공통 아이템 생성은 별도 GUI 구성 요소로 분리해 페이지별 책임을 작게 유지한다.
- GUI 액션은 문자열을 직접 비교하는 대신 파싱 가능한 액션 값으로 표현해 UUID, 슬롯, 페이지, 파티 규모를 안전하게 전달한다.
- `MazeRuntimeService`는 GUI가 필요한 받은 초대, 세이브 목록, 순위표 데이터를 비동기 API로 제공한다.
- `PartyService`는 특정 플레이어에게 온 유효한 초대를 읽기 전용 목록으로 제공한다.
- 기존 명령 실행 경로와 GUI는 동일한 런타임 메서드를 사용해 동작 차이를 만들지 않는다.

## 데이터와 이벤트 흐름

1. `/maze`가 `MazeMenu.openMain`을 호출한다.
2. 메뉴는 현재 파티와 실행 상태를 읽어 상태형 대시보드를 구성한다.
3. 클릭 액션은 소유 플레이어, 권한, 현재 화면을 검증한 뒤 런타임 메서드를 호출한다.
4. 세이브와 순위표 조회는 비동기로 실행하고 Bukkit 메인 스레드에서 현재 열려 있는 동일 화면만 갱신한다.
5. 상태 변경 후에는 성공·실패 메시지를 전달하고 관련 화면을 다시 열어 최신 상태를 표시한다.
6. 정답 입력 모드는 플레이어별 만료 시각을 저장하고, 비동기 채팅 이벤트에서 메시지를 가로챈 뒤 메인 스레드로 제출을 넘긴다.

## 오류와 안전성

- 모든 GUI 클릭과 드래그는 취소해 아이템 이동을 막는다.
- 메뉴 소유자 UUID와 최상단 인벤토리를 확인해 다른 플레이어 또는 하단 인벤토리 클릭을 무시한다.
- UUID, 슬롯, 페이지, 파티 규모가 잘못된 액션은 실행하지 않고 메뉴를 안전하게 닫는다.
- 비동기 결과가 돌아왔을 때 플레이어가 오프라인이거나 다른 화면을 보고 있으면 화면을 갱신하지 않는다.
- 관리자 액션은 메뉴 노출 여부와 무관하게 실행 직전에 권한을 다시 확인한다.
- 사용자 소유 서버 설정 및 월드 데이터는 수정하거나 커밋하지 않는다.

## 테스트와 검증

- GUI 액션 인코딩·파싱과 잘못된 입력 거부를 단위 테스트한다.
- 받은 파티 초대 조회가 다른 파티의 초대를 포함하고, 수락·거절 후 사라지는지 단위 테스트한다.
- 세이브·순위표용 비동기 조회 API가 기존 접근 권한과 필터를 유지하는지 테스트한다.
- 전체 Gradle 테스트와 빌드를 실행한다.
- 테스트 서버 시작 검증으로 플러그인이 `READY` 상태가 되고 명령·리스너 등록 오류가 없는지 확인한다.
- 실제 서버 설정·월드 변경 파일은 검증 전후 diff에서 보존됐는지 확인한다.

## 완료 기준

- 일반 플레이어가 파티 구성부터 시작·재개·힌트·정답·퇴장까지 `/maze` 하위 명령을 추가로 입력하지 않고 수행할 수 있다.
- 운영자가 권한 범위 안에서 주요 관리 기능과 세이브 관리를 GUI로 수행할 수 있다.
- 기존 명령 동작과 자동 완성이 유지된다.
- 모든 새 단위 테스트, 기존 테스트, 빌드, Paper 시작 검증이 성공한다.
