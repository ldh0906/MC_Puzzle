## 화면과 조작 구조

메인 안내 문자열은 다음 동작을 직접 지정한다.

- 최상위 플레이어가 화면의 알파벳을 클릭해 문제를 선택한다.

- 허용 형식은 한글, 영어 소문자, 숫자이며 띄어쓰기는 쓰지 않는다.

## 보호 및 구현 방식

### MPQ 단계

- `(listfile)`을 정상적으로 제공하지 않으며 일반적인 Python MPQ 열거가 실패한다.
- 알려진 내부 경로인 `staredit\\scenario.chk`를 직접 지정하면 핵심 CHK를 정상 추출할 수 있다.
- BGM은 `M0_0.ogg` 계열 66조각, `M1_0.ogg` 계열 82조각의 이름으로 참조된다. 런타임에서 조각 단위 스트림을 다루는 구성으로 보인다.

### CHK 단계

- `STRx` 섹션 크기는 5,753,240 bytes다.
- 일반 문자열 테이블로 쓰이는 앞부분은 약 87,500 bytes다.
- 뒤의 약 5,665,740 bytes는 EUD 객체/트리거 페이로드다.
- 일반 `TRIG`의 71개 트리거는 대형 EUD 페이로드를 실행하기 위한 부트스트랩에 가깝다.
- CHK 마지막의 `ISOM`은 크기가 음수로 해석되는 고의적인 파서 함정이다. 유효 데이터는 그 직전 `UPRP`까지 완전하게 순회된다.

### 정답 판정

정답은 일반 문자열 목록에 평문으로 나란히 저장돼 있지 않다. 채팅을 읽는 EUD 코드에서 비교하도록 컴파일돼 있어 `speller`, `rotavator` 같은 답을 바이너리 단순 검색으로 찾을 수 없다. 그래서 별도 공략 문서에서는 다음을 분리했다.

- 문제 규칙으로 직접 유일하게 도출되는 답
- 화면 배치 복원까지 끝났지만 실제 런타임 입력은 아직 검증하지 않은 답
- EUD 비교 루틴 추가 역분석이나 실플레이 검증이 필요한 항목
